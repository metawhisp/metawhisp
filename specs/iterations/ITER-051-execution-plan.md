# ITER-051 — Execution plan (детальный, по пунктам)

> Компаньон к `ITER-051-free-offline-first-class.md` (там — сырые находки ревью
> с evidence). Здесь — рабочий план: у каждого пункта user story, чек-лист,
> definition of done и corner cases. Персоны: **P-a** — фри без ключей/модели;
> **P-b** — фри с активной локальной MLX-моделью.

## Общий конвейер (DoD каждого батча, поверх пунктовых DoD)
1. TDD, где есть seam: красный тест → фикс → зелёный.
2. `swift build` + `swift test` — 0 ошибок, 0 падений.
3. Многоагентное adversarial-ревью диффа батча → все подтверждённые находки закрыты.
4. Хот-свап → ручной прогон пользователем по чек-листу батча.
5. После «ок» — атомарные коммиты (один пункт = один коммит).

## F1 — «Локальная модель работает по-настоящему»

### F1.0 (внеплановый, найден перепроверкой F1.1) Локальная генерация была сломана с рождения — ✅ ПОЧИНЕНО + ВЕРИФИЦИРОВАНО
- **Корень 1:** `sampleTokenSync` передавал softmax-вероятности в `MLXRandom.categorical`, который ждёт сырые логиты → почти равномерный сэмплинг из 200k словаря → многоязычный шум на КАЖДОЙ temperature>0 генерации (все прод-пути). **Корень 2:** стоп только по tokenizer eos (199999), а чат Phi-4 заканчивается `<|end|>` (200020) → генерации всегда до потолка токенов.
- **Фикс:** categorical(scaled) напрямую (оба сэмплера) + `stopTokens`-set из config.json eos_token_id ∪ tokenizer eos ∪ `<|end|>`.
- **Верификация (2026-07-07, под RAM-вотчдогом):** эталон mlx_lm на том же чекпойнте; токенайзер Swift == HF (ids идентичны); после фикса — quality: ratio 0.6-0.9, 0.6-2.0 с (было 8.3k мусора/17-20 с); stress: пик 3635 МБ стабилен × 8 генераций, worst-case 8.6 с; unload → throw → cloud-фоллбэк. Тесты-стражи: LocalLLMStressTests / LocalLLMQualityTests / LocalLLMTokenizerDiagTests (gated `MW_LOCAL_STRESS=1`; металиб копируется к xctest-бинарю).
- **Известное ограничение:** 3.8B на длинном (>800 симв.) русском входе местами пережимает детали — для длинных транскриптов облако точнее; честные ожидания в копирайте (F6).

### F1.1 Local-first роутинг в TextProcessor (structured/translate) — ✅ на диске + ВЕРИФИЦИРОВАН на реальном инференсе
- **US:** Как P-b, я хочу, чтобы Structured-диктовка и перевод обрабатывались локальной моделью, чтобы обещание «on-device вместо Pro/ключа» было правдой.
- **Чек-лист:**
  - [x] Красный тест приоритета маршрутов (`TextProcessorRoutingTests`)
  - [x] `resolveRoute(localReady/isPro/hasKey)`: local > proxy > direct
  - [x] `processLocally`: тот же language-pin промпт; maxUserChars 6000; динамический maxTokens ∝ входу (min 256, max 1536) — ограничивает latency и цену вырожденных зацикливаний
  - [x] Фоллбэк на облачный путь при любом сбое локального
  - [x] `translateOnly` — та же ветка
- **DoD:** structured/Right ⌥ у P-b идут локально (лог `[TextProcessor] LOCAL:`); у P-a/Pro без модели поведение байт-в-байт прежнее; тесты зелёные.
- **Corner cases:** модель выгрузилась между `isReady` и вызовом → фоллбэк без крэша; пустой ответ → фоллбэк; текст >6000 симв. → честная обрезка (до F1.2); Pro с включённой локальной → локальная приоритетнее (документированное обещание тумблера).

### F1.2 Контекст-бюджет: чанкинг вместо обрезки 2000 симв.
- **US:** Как P-b, я хочу, чтобы саммари/экстракция часового митинга покрывали ВЕСЬ транскрипт, а не первые ~2 минуты, чтобы local-результаты были полноценными.
- **Чек-лист:**
  - [ ] `LocalLLMService`: `summarizeInChunks(system:user:chunkChars:)` — map-reduce: чанки ~6000 → частичные результаты → финальный проход
  - [ ] `StructuredGenerator` local-ветка (title/overview/action plan) → чанкинг
  - [ ] `MemoryExtractor`/`TaskExtractor` local-ветки: `maxUserChars` 2000 → 6000 + чанкинг длинных
  - [ ] Юнит-тест чанкера: разбиение по границам предложений, ни один символ не потерян, 1 чанк = 1 проход (без reduce)
- **DoD:** транскрипт 40k симв. у P-b даёт recap, упоминающий контент из ПОСЛЕДНЕЙ трети митинга; время генерации логируется.
- **Corner cases:** пустой/короткий текст (1 чанк, без reduce); чанк без единой границы предложения (жёсткий срез); отмена/выгрузка модели между чанками → честный fail, не частичный результат как полный; reduce-промпт сам не превышает бюджет (итеративный fold при >8 чанках).

### F1.3 Интеграционные ридеры включают локальную модель в гейт

### F1.4 Честный тумблер + isLoading guard — ✅ на диске
- **US:** Как P-b, я хочу, чтобы OFF выгружал модель (−3 ГБ RAM) и реально останавливал локальный роутинг, а повторный клик по «Load now» не запускал параллельную загрузку.
- **Чек-лист:**

- **DoD:** OFF → RAM падает (Activity Monitor), все local-ветки перестают срабатывать (isReady=false); двойной клик «Load now» → одна загрузка (лог «ignored»).

### F1.5 ⚠️ РАЗВИЛКА (нужно решение): MetaChat и локальная модель
- **Вариант (a):** деградированный локальный чат — без tools, с ограниченным контекстом (последние N сообщений + top-K memories), честный бейдж «Local mode — no tools».
- **Вариант (b):** только честный копирайт: убрать «chat» из обещаний локальной секции + LLMAccessBar объясняет «MetaChat needs Pro or API key».
- **Рекомендация: (a)** — чат без инструментов, но с памятью в контексте, реально полезен и является главной «second brain»-фичей; (b) оставляет дыру в ценности фри-тира. Трудозатраты (a) ≈ 0.5–1 день.
- **DoD (a):** P-b задаёт вопрос в MetaChat → ответ локальной моделью с подмешанными memories; бейдж «Local»; tools-функции не рекламируются модели. **DoD (b):** ни одна поверхность не обещает локальный чат.
- **Corner cases (a):** вопрос про задачи («что у меня в TODO») — модель без tools честно говорит, что видит только контекст; длинная история чата → усечённое окно; переключение на Pro посреди сессии → следующий ответ через прокси с tools.

### F1.8 Re-drain очередей при готовности модели — ✅ на диске
- **US:** Как P-b, я хочу, чтобы разговоры, накопившиеся до/во время ~12 с загрузки модели, извлеклись сразу после её готовности, а не после следующего митинга.
- **Чек-лист:** [x] Combine-подписка в AppDelegate на `$isReady` (removeDuplicates, filter true) → `backfillPending()` обоих экстракторов.

- **Corner cases:** покрывает ВСЕ пути загрузки (автолоад/тумблер/Load now); повторные load/unload/load → дрейны идемпотентны (guard пустой очереди); degraded store → дрейн сам не пишет (гейт ITER-049 внутри).

### F1.9 Прерываемая локальная генерация — ⏳ в работе

- **Чек-лист:**
  - [ ] `runGenerationSync` принимает `isCancelled: () -> Bool`, проверка на каждой итерации decode
  - [ ] `AsyncStream.onTermination` + отмена `pendingGeneration` → взводят флаг
  - [ ] `completeBlocking` пробрасывает CancellationError
- **DoD:** отмена потребителя останавливает цикл ≤1 токена спустя (лог «generation cancelled after N tokens»); очередь следующего вызова стартует немедленно.
- **Corner cases:** отмена во время prefill (проверка сразу после prefill); отмена уже завершённой генерации → no-op; `clearCache()` выполняется и на отменённом пути (не копить Metal-буферы).

### F1.10 BYOK-чат: tools отвергаются собственным validate()
- **US:** Как фри-юзер со своим API-ключом, я хочу, чтобы поисковые tools чата работали, а не падали «Unknown tool» после того, как их предложили модели.

- **Corner cases:** модель зовёт несуществующий tool → прежний честный отказ; пустые аргументы → валидация аргументов не тронута.

## F2 — «Ничего не падает молча»

### F2.1 Right ⌘ виснет в THINKING навсегда (P-a)
- **US:** Как P-a, я хочу мгновенный честный ответ «нужен Pro/ключ/локальная модель» вместо вечного THINKING, чтобы не считать аппку зависшей.
- **Чек-лист:** [ ] guard hasLLMAccess ДО перехода в .thinking → новое состояние `.needsAccess` (пилюля: короткий текст + «Open Settings»); [ ] авто-дизмисс 6 с.
- **DoD:** P-a долгим Right ⌘ получает ответ-подсказку ≤1 с; THINKING недостижим без LLM-доступа.
- **Corner cases:** P-b с моделью в процессе загрузки → «Local model is loading…» (не needsAccess); доступ появился (ключ вставлен) → следующий вопрос работает без рестарта.

### F2.2 Состояние ошибки у пилюли
- **US:** Как фри-юзер, я хочу видеть причину прямо на пилюле, когда диктовка не удалась (слишком коротко/нет модели/ошибка движка), а не мёртвую тишину.
- **Чек-лист:** [ ] `RecordingOverlay`/варианты пилюли: state `.error(String)` (красный акцент, 3-4 с, автогашение); [ ] `TranscriptionCoordinator`: все ветки discard/fail публикуют короткую причину; [ ] маппинг технических ошибок в человеческие фразы.
- **DoD:** двойной случайный тап Right ⌘ → пилюля показывает «Too short — try again» вместо исчезновения; ошибки движка видимы без открытия попапа.
- **Corner cases:** ошибка во время видимого другого состояния (error перекрывает); повторная диктовка сразу после — error сбрасывается; Shrek-режим тоже показывает (общий стейт, не пер-вариант).

### F2.3 Онбординг: провал/долгая загрузка модели видимы (NEXT-гейт)
- **US:** Как новый юзер, скачавший 950 МБ, я хочу видеть «Loading model… first time takes a few minutes» и RETRY при провале, а не вечно disabled NEXT при ✓-галке.
- **Чек-лист:** [ ] `.loading`-состояние между download-done и loaded (публикация из FREE-1 sink); [ ] catch авто-лоада → `coordinator.lastError` + строка ошибки на странице + RETRY (перезапуск load, не download); [ ] sink не молчит при nil whisperEngine.
- **DoD:** обрыв загрузки → страница показывает причину + RETRY; успешная долгая загрузка → индикатор, NEXT открывается сам.
- **Corner cases:** повреждённая директория модели (isDownloaded=true, load падает) → RETRY предлагает re-download; юзер ушёл со страницы во время загрузки → состояние живёт в координаторе, вернулся — актуально.

### F2.4 Try-it страница: фидбэк отброшенных попыток
- **US:** Как новый юзер, чья первая попытка отброшена (<0.3 с/тишина), я хочу «Didn't catch that — try again» и сброс фазы, а не вечный фейковый «recording».
- **Чек-лист:** [ ] `handleStageChange` на `.idle` в фазе 1/2 без результата → фаза 0 + инлайн-подсказка (из lastError или generic).
- **DoD:** двойной тап на try-it → страница возвращается в исходное с подсказкой; таймер фаз не едет вперёд при idle.
- **Corner cases:** успешный результат после неудачной попытки → подсказка очищается; hallucination-фильтр (lastResult ставится) → фаза 3 как раньше.

### F2.5 Перевод без доступа: не вставлять исходник молча
- **US:** Как P-a, нажав Right ⌥, я хочу явную ошибку «Translation needs Pro / API key / local model», а не свои же слова без перевода, будто всё сработало.

- **DoD:** P-a: Right ⌥ → ничего не вставлено + видимая причина; P-b: перевод работает (локально).
- **Corner cases:** режим clean+translate — clean-часть применена, перевод нет → тоже ошибка, не «полууспех»; translate selected text — та же честность (см. F2.7).

### F2.6 Атрибуция движка

### F2.7 Selection-translate: причина вместо анонимного бипа

## F3 — Model management честный

### F3.1 Целостность закачки: обрыв ≠ «downloaded»
- **US:** Как новый юзер с оборвавшейся закачкой, я хочу «Resume download», а не ✓ и мёртвую диктовку.
- **Чек-лист:** [ ] маркер завершённости (манифест/`.complete`-файл после верификации всех файлов) — `isDownloaded` проверяет маркер, не существование папки; [ ] миграция: существующие полные модели получают маркер при первом успешном load; [ ] неполная папка → состояние «Resume · X%».
- **DoD:** убить аппку на 50% закачки → рестарт показывает Resume, не ✓; загрузка модели без маркера не считается downloaded.
- **Corner cases:** юзер руками удалил файл из папки модели → load падает → статус откатывается в Resume/Re-download (см. F2.3 corner); диск кончился в конце закачки → честная ошибка + partial сохранён для resume.

### F3.2 Провал закачки: retry вместо замёрзшего прогресса
