# ITER-048 — Стоимость ASR без потери качества

**Source:** CF billing 2026-06-10 — 100% Workers AI neurons = ASR (Whisper), 37.8k аудио-сек/день
(10.5 ч) при реальных созвонах ~3.5 ч. Причина ×3: live-партиалы (1×) + финальный dual-stream
проход mic и system раздельно (2×). ~$0.30/час аудио на Workers AI.
**Принцип (решение продукта, 2026-06-10):** качество сохранённого транскрипта — максимум;
сильная модель не используется там, где её качество никому не видно; мусор лечится ITER-046, не моделью.

## Решения

### C1 (P1, репо воркера `metawhisp-api`). ASR-бэкенд → Groq whisper-large-v3-turbo
ТА ЖЕ модель, что сейчас на Workers AI → качество финального транскрипта не меняется. Цену Groq
проверить на актуальном прайсе перед переключением; исторически в разы дешевле CF (~$0.30/ч).
- [ ] `/api/pro/transcribe`: маршрут на Groq audio API, CF Workers AI оставить fallback'ом при 5xx/429
- [ ] Прокинуть `language` и `prompt` как сейчас (initial_prompt)
- [ ] **Форвардить per-segment метрики** (`avg_logprob`, `compression_ratio`, `no_speech_prob`) в
      `segments` ответа — клиент уже парсит их (f21b02e), но прокси их сейчас НЕ отдаёт, поэтому
      confidence gate (ITER-046 B) для Pro-пользователей инертен на cloud-пути. Без этого пункта
      главный анти-галлюцинационный фильтр не работает именно там, где жалуются.
- [ ] Лог: serviceId + audio-секунды + бэкенд на каждый запрос (закрывает «откуда расход» навсегда)
- [ ] Verify: один митинг → качество сегментов/таймстампов эквивалентно (segments в verbose_json)

### C2 (P2, этот репо). Live-партиалы — слабая/локальная модель
Партиалы видит только копайлот, в сохранённый транскрипт они не попадают (dormant reuse-путь) —
large-turbo здесь не нужен.
- [ ] Настройка `liveTicksPreferLocal` (default: on, если локальная модель скачана):
      `LiveMeetingAdvisor.processChunk` берёт локальный `whisperEngine`, если `isModelLoaded`,
      иначе `activeEngine` (как сейчас)
- [ ] ВАЖНО: Pro-пользователям модель выгружается при старте (auto-switch cloud, экономия RAM) —
      для live-тиков загружать `base`/`small`, НЕ large (RAM + скорость); либо качать base при
      первом митинге с включённой настройкой
- [ ] ВАЖНО: WhisperKit transcribe не гарантирует потокобезопасность — сериализовать вызовы
      (live-тик vs диктовка Right ⌘ во время митинга) через actor/очередь в WhisperKitEngine
- [ ] Деградация подсказок копайлота допустима (gate+коуч работают по смыслу, не по дословности)

### C3 (P3, этот репо). Не платить за пустое
- [ ] Финальный проход: stream без озвученных чанков → 0 вызовов (проверить, что уже так)
- [ ] Live-тик и финальный чанк не отправляются, если VAD-trim оставил < 1 сек речи
- [ ] Манифест аудио-минут в лог при стопе митинга: live X мин + final Y мин (видно ×N сразу)

### Отклонено (фиксируем почему)
- Сбор финального транскрипта из live-партиалов (−66%): теряет Me/Them-диаризацию →
  противоречит «качество максимум». Вернуться, только если C1+C2 не хватит.
- Уменьшение модели финального прохода: то же.

## Ожидаемый эффект
C1: −70%+ от всего ASR-расхода при том же качестве. C2: −1/3 объёма аудио в облако.
Вместе: 2-часовой созвон ≈ 4 ч аудио по дешёвому тарифу вместо 6 ч по дорогому.

## Порядок
C1 — сразу (отдельный репо, нулевой риск качества). C2 — после, требует решения по RAM/модели
для Pro. C3 — попутно. Качество транскрипта дополнительно поднимает ITER-046 (итерации A+B) —
делать параллельно с C1.
