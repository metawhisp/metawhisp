2.3b closes the second review of 2.3 (`2.3-reviews.md`). Each round was a separate Claude reviewer with
no write access; each printed `git status --porcelain | shasum` and `git diff | shasum` at its start

scratch folder.

## Round 1 — ACCEPT, 2 P2 and 3 groups of P3 (all fixed before round 2, tests first)

| # | Finding | Fix |
|---|---|---|
| P2-1 | A regression 2.3b brought: `insideChoice` also dropped real fields inside a combobox or list box wrapper (the ARIA 1.1 layout), and a dropped field skipped the secret check — a card number inside `role=combobox` no longer flagged the page, and a select's account e-mails were listed | A text field, select, textarea or editable region is never "inside a choice": it is reported and checked like any field. | P2-2 | A select in a GET form with no action lost its identity when the form sent itself: `formAction` was the page's address, query included, so `holds` answered gone and the choice was offered again | A GET form's destination is its action without query and fragment, as a server gets it. | P3-1 | Every list box counted as a custom select, so a plain list's links and buttons were dropped; tree items inside a select's popup too | A list box counts only when it pops up (`aria-expanded`, or `aria-haspopup` other than false); tree items are exempt like options |
| P3-2 | The `holds` origin check used the page's own `URL`, which a page can replace | The origin is worked out in Swift (`ActionScript.origin(of:)`) and compared with `location.origin` |
| P3-3 | A test repeated an engine the file already had; known limits missing | Reused `priceOrDone()`; limits written in the plan: a button inside an ARIA 1.1 wrapper, a select whose change rewrites its own row or sends a POST form with no action, `<input role=combobox>` offering nothing until 2.4 |

The reviewer's answers: dropping controls is safe for acting, because the act finds its element with the
same walk; the memory is read only to leave an option out; the 300 ms wait after a select changes no
