Round 18 confirmed fixed: a component read twice ("OTPOTP"), words in separate tags ("Enter" "OTP").

Findings (both confirmed in the code):
  1. the markup reading never entered a shadow root, so a word held in a nested component that no slot
     shows was never read;
  2. a label mixing seams the page draws as a break and seams it draws as nothing ("Enter" on its own line,
     then "O<b>TP</b>") read "EnterOTP" or "Enter O TP"; \botp\b matched neither. Same class: an invisible
     format character ("Pass&shy;word") became a space, so "passw" missed.
Cause: the classifier got a flat string whose every seam was already decided one way; how the page draws a
seam depends on CSS the reader cannot know.
Fix (owner layer: the label reader and the classifier, the only consumers of these words): every seam — a
text-node boundary, or a run of invisible format characters (\p{Cf}) — is marked U+200B and read both ways
at once, in one linear match: long words on the words read run together; short words (pwd, otp, 2fa, cvv,
cvc, csc, mm yy) standing alone, each end a space, the edge or a seam, a seam inside read as nothing. The
markup reading enters shadow roots.
