# ITER-053: Screen Intelligence — флагманская фича {#root}

> Статус: DRAFT — план на ревью. Создано 2026-07-12 по решению основателя:
> «надо делать флагманом… полноценная важная полезная фича, которая анализирует
> и может ставить задачи полноценные, помнит что происходило».
> База фактов: код-аудит скрин-пайплайна + конкурентный ресёрч 2026-07-12
> (десктоп-конкурент = Rewind-фича со скриншотами→H.265+OCR+эмбеддинги; Screenpipe =
> open-source 24/7 захват; Rewind.ai мёртв после покупки Meta дек-2025).

---

## 0. TL;DR · Позиционирование · DoD {#top}

**Сегодня** скрин-фича — полуживая: захват выключен по умолчанию, OCR-история
растёт бесконечно без очистки, задачи staged-молчаливые, proactive — Pro-only,
семантического поиска по прошлому нет, и всё это молча умирало без LLM-доступа
(баг логаута, починен в ITER-052).

**Флагман** = три обещания пользователю (архитектура — copy-first с референса
Rewind/Recall-класса: **пиксели для человека, OCR-текст для ИИ**):
1. **«Помнит, что происходило» — визуально.** Таймлайн с реальными кадрами экрана
   (отмотка как в Rewind) + вопрос MetaChat «что я делал вчера по X?» /
   «где я видел ту ссылку?» через семантический поиск по истории.
2. **«Ставит полноценные задачи»** — увиденное на экране превращается в задачи
   с доказательством (цитата с экрана), без дублей, с follow-up на повторы.
3. **«Локально и стираемо».** Кадры и текст живут ТОЛЬКО на устройстве (FileVault
   шифрует диск), история ограничена сроком (30 дней дефолт) и удаляется одной
   кнопкой; анализ — на устройстве (Phi-4 / Apple FM). Решение основателя
   2026-07-12: пиксели ПИШЕМ (как референс), клин — не «без пикселей», а
   «локально + bounded + one-click delete» против облачных пайплайнов.

**Козырь против конкурентов (Screenpipe и др.):** локальная модель уже работает (ITER-051/044) →
весь анализ экрана бесплатный, приватный и безлимитный (нет 30-калл/час
облачного капа) + Mac-native полировка против dev-flavored Screenpipe.

### Definition of Done (флагман, весь ITER-053) {#top.dod}
1. Retention: сырой OCR старше N дней (дефолт 30) автоматически удаляется;
   «Delete screen history» в Settings стирает всё скрин-хранилище мгновенно.
2. Free-юзер с локальной моделью получает ВСЁ (экстракция, realtime-задачи,
   proactive-инсайты) — ни одного молчаливого «No LLM access — skipping».
3. В MetaChat работает вопрос «что я делал вчера/на этой неделе по <тема>» —
   ответ опирается на семантический поиск по истории экрана, с указанием
   app/времени.
4. Задачи с экрана: с evidence-цитатой, дедуп против существующих, follow-up
   («видел 3 раза — не сделал»), opt-in уведомление о новых staged.
5. Таймлайн показывает реальные кадры экрана с отмоткой по дню; кадры живут
   только локально (guard-тест I1: image→network путей нет) и подчиняются
   retention/delete-all (I5). Все тесты зелёные.

## 1. Инварианты {#invariants}
- **I1 — Пиксели не покидают устройство. НИКОГДА.** Кадры экрана пишутся только
  локально; ни один пиксель не уходит ни в какое облако (включая наш Pro-proxy).
  В облако (для Pro-фоллбэка) может уходить только OCR-ТЕКСТ, как сегодня.
  Guard-тест: скрин-пайплайн не имеет путей image→network.
- **I2 — Local-first.** Каждый скрин-потребитель работает по цепочке
  local → Pro → BYOK (как ITER-051 F1). Pro-only гейтов в скрин-фичах не остаётся.
- **I3 — Staged, не auto.** Всё, что породил экран (задачи/памяти), появляется
  как staged/confirmable — никаких автодействий. (Уже так; не ломать.)
- **I4 — Существующие данные не теряем молча.** Purge — только по явной политике
  retention или явной кнопке юзера.
- **I5 — Retention распространяется на ВСЁ.** Кадры, OCR-строки, эмбеддинги —
  одна политика, одна кнопка удаления. Пиксели без срока жизни не бывают.

## 2. Итерации {#plan}

### 053.1 — Гигиена и фундамент (prereq всего остального) {#i1}
**User story:** Как пользователь, я хочу, чтобы история экрана не разрасталась
бесконечно и удалялась одной кнопкой, чтобы доверять фиче свои данные.
- [x] Retention-политика: `screenRetentionDays` (дефолт 30, 0 = вечно) + prune
      ScreenContext на старте и каждые 12ч; `observationRetentionDays` (180).
      Batch-delete (fetchCount + delete(model:where:)) — без материализации.
      `Services/System/ScreenRetention.swift`, AppDelegate.pruneScreenHistory.
- [x] Settings: пикер «Keep history» (7/30/90/Forever) + «Delete screen
      history…» с confirm — ВНЕ if-гейта (доступно и при выключенном захвате).
      deleteAll чистит: обе таблицы + staged/dismissed (incl. legacy
      isDismissed) скрин-задачи + скрин-памяти + in-memory буферы
      (`ScreenContextService.clearInMemory`) + Obsidian-файлы артефактов +
      MCP-снапшот. Purge-fence (epoch) в ScreenExtractor,
      RealtimeScreenReactor И capture-петле — in-flight работа не воскрешает
      удалённую историю.
- [x] Тесты: ScreenRetentionTests 9/9 (границы, 0=вечно, независимые окна,
      delete-all с артефактами и ID для внешних хуков).
      Codex-ревью 8 раундов: билд+полный сьют зелёные; все P1/P2 закрыты
      (последний — комментарий о +60s slack).
- [ ] Убрать мёртвую проводку: `screenContext` из MemoryExtractor/TaskExtractor.
- [ ] Унифицировать подсчёт «время в приложении»: Dashboard считает из сырых
      ScreenContext, DailySummary — из ScreenObservation → один helper.
- [ ] Guard-тест I1 (image→network) — вместе с 053.3 (пикселей ещё нет).

### 053.2 — Local-first везде, честный статус {#i2}
**РЕШЕНИЕ ПО ДВИЖКУ (основатель, 2026-07-12):** ядро флагмана (кадры, таймлайн,
поиск) AI не требует и работает у всех. AI-слой: на macOS 26+ Apple FM
включается АВТОМАТИЧЕСКИ (zero-setup, юзер ничего не выбирает и не качает);
фоллбэк — Pro-облако; Phi-4 — опция, не опора. «Local-first» = «FM-first,
авто», а не «юзер сам скачал 2.2 GB».
**User story:** Как Free-юзер с локальной моделью, я хочу полный анализ экрана
без подписки и ключа, и видеть, что он реально работает.
- [ ] Авто-включение Apple FM: на macOS 26+ при доступности
      (`SystemLanguageModel.availability == .available`) активировать FM как
      локальный движок без действий юзера (см. ITER-044).
- [ ] ProactiveContextService: убрать hard Pro-гейт → hasLLMAccess-цепочка
      (local → Pro → BYOK), как у остальных.
- [ ] RealtimeScreenReactor: локальный путь без 30/час капа (кап оставить только
      для облачных вызовов).
- [ ] Settings-карточка «Screen Intelligence»: статус-строка (captures сегодня,
      последний разбор, каким движком — «Phi-4 on-device» / «Pro cloud»),
      вместо разрозненных тумблеров.
- [ ] Ни одного молчаливого skip: нет LLM — карточка показывает «включи локальную
      модель или Pro», а не тишина в логе.
- [ ] Тесты: гейтинг-матрица (free+local / free+key / pro / ничего).

### 053.3 — Визуальная память: кадры + таймлайн-отмотка (категорийный стандарт Rewind/Recall) {#i3}
**User story:** Как пользователь, я хочу отмотать время назад и УВИДЕТЬ экран,
каким он был («покажи тот дизайн/график/страницу»), а не только текст.
- [ ] v1 — кадры: при каждом захвате (тот же 30s/window-change тик) сохранять
      сжатый кадр (HEIC/JPEG, target ≤200KB) рядом с ScreenContext-строкой
      (файл в Application Support/MetaWhisp/Screens/, имя = id строки).
      Диск-расчёт: ~300–1000 кадров/день × ~100–200KB ≈ 30–200MB/день →
      ~1–6GB на 30-дневном retention (оценка, замерить в smoke).
- [ ] Те же privacy-фильтры, что у OCR (пароль-менеджеры, blacklist, только
      фронт-окно) — кадр и текст всегда из ОДНОГО снимка.
- [ ] RewindView v2: таймлайн с миниатюрами, клик = полный кадр, скраб по дню
      (референс UX: Rewind/Recall).
- [ ] Retention/delete-all из 053.1 покрывает кадры (I5); guard-тест I1
      (image→network путей нет).
- [ ] v2 (отдельно, после smoke): почасовая упаковка кадров в H.265-чанки
      (AVAssetWriter/VideoToolbox, БЕЗ ffmpeg-зависимости — нативно) — как у категорийных конкурентов;
      даёт ~5–10× экономию диска на статичных экранах (оценка). Решение после
      замера реального диска v1.
- [ ] Тесты: кадр пишется/не пишется по тем же гейтам, retention чистит файлы
      с строками, delete-all не оставляет сирот.

### 053.4 — «Помнит, что происходило»: семантический поиск {#i4}
**User story:** Как пользователь, я хочу спросить «что я делал вчера по проекту X»
или «где я видел ссылку про Y» и получить ответ с временем и приложением.
- [ ] Эмбеддинги для ScreenObservation (contextSummary+currentActivity) — тем же
      EmbeddingService, что memories/conversations (background, батчами).
- [ ] Новый chat-tool `search_screen_history(query, day_range)` → топ-K
      observations c app/временем/summary; вписать в оба пути (Pro tools +
      локальный text-loop) — синк со схемой (ChatToolSchemaSyncTests).
- [ ] RewindView: поиск переводится на семантику (fallback — текущий substring),
      фильтр по приложению.
- [ ] Backfill: одноразовая фоновая индексация существующих observations.
- [ ] Тесты: tool-схема синк, ранжирование (мок-эмбеддинги), backfill идемпотентен.

### 053.5 — «Задачи полноценные» {#i5-tasks}
**User story:** Как пользователь, я хочу, чтобы увиденные на экране обязательства
становились задачами с доказательством, без дублей, и чтобы повторно висящее
на экране напоминало о себе.
- [ ] Follow-up: если один и тот же контент (по эмбеддинг-близости) виден ≥3 раз
      за N дней и staged-задача не промоутнута — поднять приоритет + один
      digest-инсайт («висит 3 дня: …»).
- [ ] Дедуп staged-задач против ВСЕХ задач (сейчас — только против недавних).
- [ ] Opt-in уведомление «новые staged-задачи за день: N» (digest, не по одной).
- [ ] Промоут-флоу в Tasks: evidence-цитата видна при подтверждении.
- [ ] Тесты: follow-up триггер, дедуп, digest-группировка.

### 053.6 — Onboarding и дефолты (продукт-решение с основателем) {#i6}
**User story:** Как новый пользователь, я хочу понять ценность и включить фичу
за один экран, зная, что именно хранится.
- [ ] Onboarding-карточка: «текст, не скриншоты; на устройстве; N дней; кнопка
      удалить всё» + запрос Screen Recording пермишена в контексте ценности.
- [ ] Решить дефолты: captureInterval (30s ок?), screenExtractionEnabled=true
      остаётся, realtimeReactor — вкл. при наличии локальной модели?
- [ ] Маркетинг-строка для сайта/аппкаста (privacy-клин против облачных конкурентов) — «текст,
      не видео» (сайт не трогаем в релизном цикле — отдельно).

## 3. Corner cases (тестировать в каждой итерации) {#corners}
- Пустая история / выключенный захват → все фичи деградируют объяснимо, не молча.
- Смена retention с 30 → 7 → prune не съедает observations, на которые ссылаются
  задачи/памяти (FK-осиротение — таскам evidence хранить копией, не ссылкой).
- Массовый purge во время активного hourly-разбора (гонка) — extractor
  переживает исчезновение строк.
- Семантический поиск при 0 эмбеддингов (до backfill) → substring-fallback.
- Локальная модель занята диктовкой → скрин-разбор ждёт в FIFO, не падает.
- Guard I1: PR с записью изображения из скрин-пайплайна валит swift test.
