# FEAT-0005: Automatic tasks are suggestions the user accepts {#root}

Approved by the owner on 2026-11-26 («Да, утверждаю»), after «окей поправь у меня и эти правила сделай для всех в
дальнейшем». Going forward only: tasks other users already have are not touched. Target release 1.4.9, from 1.4.8
(`a672b50`).

## 0. Invariants (read first) {#invariants}

- **I1.** An automatically extracted task is never written to the task list. Every automatic result is a draft
  (`TaskItem.status == "staged"`) the user accepts (✓) or drops (✗). That includes "remind me" / "add a task" said in
  a dictation (owner Q1). Only the voice agent (MetaChat / voice question tools) writes a task directly.
- **I2.** A draft never becomes a task by itself: the promotion loop and the hourly re-rank touch screen candidates
  only (`screenContextId != nil`), never a voice draft.
- **I3.** A draft lives 7 days (owner C1). Expiry is computed on read (`TaskHygiene.isStaleUnreviewedCandidate`);
  there is no expiry writer; accepting an expired draft is refused.
- **I4.** Accepting from Tasks and from the after-call card makes one task: the draft row keeps its id and only its
  status changes. Accept and drop write on a fresh fetch by id in a new context (stale-save rule).
- **I5.** No notification for a draft, no vault (Obsidian) file for a draft; the vault file is written on accept.
- **I6.** No word lists in any language decide anything new here (K18): the model gives kind, evidence and flags;
  code checks them by structure.
- **I7.** Nothing is added to the menu-bar popover.

## 1. Cause and the owning layer {#cause}

Audit of the 551 open automatic tasks on the owner's Mac (2026-11-25/26): 44 real, 352 instructions to AI tools, 123
duplicates, 23 invented or garbled owners. Real: dictation 32/531 (6%), meetings 12/20 (60%). The owner archived the
507 junk tasks on his Mac on 2026-11-26 (backup kept); this spec is the rule for everyone afterwards.

Every automatic voice task is made in one place: `TaskExtractor.extractFromConversation`. Confirmed in code at 1.4.8:
1. The prompt never tells the model whether the text is a dictation (mostly instructions to AI tools) or a call
   between people; it calls both "a voice-dictation conversation".
2. The code keeps whatever parses: the only check is ≤15 words. No evidence check, no source rule, none of the title
   filters screen tasks have.
3. Results go straight to the task list (`committed`) with a "Task added from Voice" notification.
4. Dedup sees 2 days and 50 rows; a dropped suggestion can come back.
5. Calendar attendee names are handed to the model "to name people", which produced owners nobody said.

Coupled layers that would break a drafts change if left alone (confirmed in code):
- `TaskPromotionService.promoteIfNeeded` promotes ANY staged row while fewer than 5 screen tasks are active.
- `TaskPrioritizationService` calls a model hourly when ≥2 staged rows exist.
- `ObsidianExporter` writes every non-dismissed task, staged included (conversation hub, meeting note, daily note,
  full export, single task).
- `ConversationDetailView` / `ConversationsView` list every non-dismissed task of a conversation as a task.

## 2. User stories {#stories}

- **S1.** As a user who dictates prompts to AI tools all day, I want none of those prompts to become tasks, so my
  task list holds only my real work. *Accept:* a dictation of instructions to an AI tool gives no draft.
- **S2.** As a user, I want "remind me to …" said in a dictation to be offered to me, so I decide whether it is a task.
  *Accept:* it lands in Tasks → Suggested with ✓ / ✗; nothing is in My tasks until ✓.
- **S3.** As a user after a call, I want the call's commitments offered in the after-call card and in Tasks, so I add
  the right ones in one click. *Accept:* ✓ in either place makes one task; the other place shows it added / gone.
- **S4.** As a user, I want a suggestion I ignored to disappear after a week, so the list does not grow. *Accept:*
  older than 7 days → not shown; ✓ on an open card after that → refused.
- **S5.** As a user, I want people named only when someone said that name, so no invented owners. *Accept:* a
  "waiting on X" draft exists only if X is spoken in the transcript.
- **S6.** As a user, I don't want the same suggestion again after I dropped it, unless I bring it up again later.
  *Accept:* re-extracting the same conversation does not bring it back; a new mention after the drop may.

## 3. Model answer {#answer}

### 3.1. Prompt {#answer.prompt}
The user prompt states the source on its own line: `SOURCE: dictation` (one person dictating, often to an AI tool or
into another app) or `SOURCE: call` (a conversation between people, lines `Me:` = the user, `Them:` = the others).
The calendar block is gone (K14). The system prompt carries the rules R4/R5/K2–K7 and the schema below.

### 3.2. Item schema {#answer.schema}
```json
{"tasks": [{"description": "Send the signed contract to Sam",
            "kind": "mine | waiting_on | asked_by_user",
            "evidence": "<the words from one fragment, copied exactly, never translated>",
            "due_at": "2026-11-27T22:59:00Z" or null,
            "assignee": "<the promisor's name exactly as spoken>" or null,
            "capture_confidence": 0.0-1.0,
            "ownership_confidence": 0.0-1.0,
            "concrete_deliverable": true | false,
            "real_world": true | false}]}
```
- `mine` — the user does it. `waiting_on` — ONLY another person's promise or offer to the user (owner Q2: the
  user's own request to someone is not tracked). `asked_by_user` — the user explicitly asked to be reminded / to add a
  task, for later.
- `real_world` — the action happens outside this computer session: with a person, money or a date; not work an AI
  tool or app is being told to do now.
- Old answers without the new fields still parse (not "unparseable", no retry); their items fail K1 and give nothing.

## 4. Rules after the model (pure, unit-tested) {#rules}
`TaskCandidateRules`, applied in this order; each drop has a reason (logged, counted by the replay).

| # | Rule | Drop reason |
|---|---|---|
| kind | kind is one of the three | `unknownKind` |
| K1 | `concrete_deliverable == true`, capture ≥ 0.8 and ownership ≥ 0.8 (missing = 0) | `belowFloor` |
| R4 | dictation: `mine` only when `real_world == true`; `asked_by_user` and `waiting_on` stay | `dictationNotRealWorld` |
| R2/K17 | evidence found in one sent fragment, ignoring case, diacritics, spaces and punctuation; at least 6 letters or digits | `evidenceNotSpoken` |
| K7 | call: `asked_by_user` evidence is on a `Me:` line | `notTheUsersRequest` |
| R2/K3 | description or assignee has a bracket placeholder (`[…]`, `<…>`, `{…}`), or the assignee is a speaker label | `placeholder` |
| K14 | `waiting_on` needs an assignee spoken in the transcript (labels stripped); `mine`/`asked_by_user` carry none | `nameNotSpoken` |
| R6 | the existing title filters: `isGenericNoise`, `validateTaskTitle`; ≤15 words | `vagueTitle` |
| K13 | due date more than 1 day in the past is cleared (item kept) | — |
| R1/K8/K9 | repeat of an existing row or of an earlier item in the same answer | `repeat` |

- **R3** (before sending): phantom phrases go — `TranscriptionCoordinator.stripHallucinationTokens` cleans a fragment;
  an empty result is dropped. Evidence is checked against what was sent. Not `isAlwaysHallucination`: its mixed-script
  check is for one short chunk, and the replay lost a whole call (16,814 characters, three scripts) to it.
- **R2 evidence pieces**: the model may shorten a long quote with an ellipsis ("…" / "..."); each piece must appear in
  the same fragment, in order.
- **K14 in scripts without spaces** (Han, Kana, Thai, Lao, Myanmar, Khmer): the name's letters must appear in the
  fragment; elsewhere the name's words must appear as whole words. The R6 word floor does not judge such titles
  (`TaskExtractionFilters.isWrittenWithoutSpaces`; it rejected every one before).
- **K17 typo tolerance**: a piece of 20+ letters in a script with spaces may differ in ONE letter (substituted,
  added or missing), strictly inside it — its first and last 3 letters exact (the model "fixes" a speech model's typo
  in its quote; replay: 3 real items lost to one changed letter). One letter at most and anchored edges, so a dropped
  two-letter "no" or "no quiero" → "yo quiero" is refused; scripts without spaces get no tolerance (a one-character
  negation). A paraphrase or a shuffle (14–24% different in the replay) is refused; under 20 letters the quote is
  exact. A speaker label the model copied with the words is taken off first. Ellipsis pieces must each have 6+
  letters and follow one another within 300 letters, so a quote cannot be stitched from words spread over a call.
- The model is asked for at most five items (the display cap; it also keeps the local route's answer whole).
- The rules run off the main actor: the typo-tolerant scan of a 100,000-character call takes seconds in a debug build.
- **K8 near-duplicate** = the same words, ignoring order, case and punctuation, and the same assignee. Without a word
  list an added word cannot be told from a negation, so any added, missing or replaced word makes it a different
  task; numbers, negation and recipient then always match and the overlap is 1.0 (≥ 0.8). The old 0.6 overlap merged
  "send budget to Nina" with "send budget to Nora".
- **K9 lifecycle** — an existing near-duplicate row blocks a new item when it is open (a committed task not done, or
  a draft within 7 days) or when the item's mention (the time of the fragment its evidence was found in: recorded,
  else saved) is not later than the row's resolution: dismissal (`updatedAt`), completion (`completedAt`), expiry (`createdAt` + 7 d).
  Done, dropped or expired work said again later may come back.
- **R5 / Q2, K2, K5, K6** have no structural signal: the prompt states them and the model's kind / flags carry them
  (`concrete_deliverable` false for status lines and small talk; no item for a command to an AI tool now). The replay
  (§7) measures them.

## 5. Drafts {#drafts}
- Saved as `staged`, no notification, no vault export (`ObsidianExporter` skips anything that is not a task and
  removes its file). Embedding as before.
- Shown at most 5 (K10), newest first (within one pass, the model's first item first), not expired:
  `TaskDrafts.visible`. The after-call card re-reads both its lists from the store after every ✓ / ✗ and when the
  extraction lands, so the next draft fills a handled slot and a draft accepted in Tasks shows there as added.
- `TaskDrafts.accept(id)`: fresh context, fetch by id → missing `gone`; committed `alreadyAdded` (no write); dismissed
  `dismissed` (refused); expired `expired` (refused); else `committed`, `updatedAt = now`, saved through
  `MutationService` (`.taskSaved` → vault file).
- `TaskDrafts.drop(id)`: staged → dismissed (`isDismissed`, status `dismissed`, `updatedAt = now`); committed →
  `alreadyAdded` (refused: never drop a task accepted elsewhere); missing → `gone`.
- `TaskItem.isTask` (not dismissed, committed or legacy nil) is the one definition of "a task" for lists outside the
  draft surfaces (conversation views, vault).

## 6. UI {#ui}
- Tasks → "Suggested" (the existing review section, renamed): voice drafts ✓ add / ✗ drop through `TaskDrafts`;
  screen candidates keep their own three buttons. At most 5.
- After-call card: "Suggested (n)" with ✓ / ✗ per draft; an accepted row moves to the action items; the card reloads
  its drafts when the extraction lands while it is open.
- Empty-state and "Extract now" texts say "suggest", not "add".
- Nothing in the menu-bar popover.

The new extractor, through the Pro server, reading the store only, on ≈100 conversations: those behind the 44 real

## 8. Corner cases {#corners}
K1 vague / low confidence · K2 status lines · K3 unresolved references · K4 public "someone should" · K5 small talk ·
K6 a command to the AI now · K7 quoted / someone else's "remind me" · K8 near-duplicates · K9 dismissal lifecycle ·
K10 cap 5 · K11 expired accept · K12 accept twice / from two places · K13 past due · K14 names only if spoken ·
K15 no notice for drafts · K16 promotion off for voice drafts · K17 evidence in the spoken language · K18 no word
lists · K19 no vault for drafts · K20 old staged rows (owner's Mac: 4, all screen, newest 2026-08-29 — outside the
window, nothing floods Suggested).

Not in this iteration: screen remarks on a task (T13), "I already sent it" → offer to tick, "make that the revised
budget" → offer to edit, dismiss reasons, projects on tasks.
