## 0. Почему порядок изменён

Мастер-план ставит первым `ITER-064` — контракты, схему V4 и 60 фикстур. Три возражения,
каждое подтверждено кодом:

1. **План противоречит собственному аудиту.** §13 аудита перечисляет 8 правок и ставит
   replay-набор *последним* пунктом, 20 кейсов. Мастер-план ставит его *первым*, 60 кейсов.
2. **Схема V4 не может быть спроектирована раньше директора.** `ITER-064.4` требует пять
   SwiftData-моделей и стадию V3→V4 до того, как существуют владелец решения (`066`) и
   доставка (`067`). Отгруженная схема необратима: откатить V4 у пользователя нельзя.
   Фикстуры пишутся против API, которого ещё нет, и переписываются в `066`.
3. **Краш и privacy-fail-open лежат в 8-й и 2-й итерации.** Обе правки — на одну строку.

## 2. ITER-064A — подтверждённые дефекты

**Статус:** активна.
**Пользовательский результат:** приложение не падает от ответа модели; выключенный
whitelist не означает «снимать всё»; сбой захвата не выключает окно навсегда;
подсказка не ждёт таск-классификатор.
**Новой архитектуры нет.** Каждая правка полезна при любом решении по остальной программе.

### User stories и приёмка

**US-064A-1 — приложение не падает от ответа модели.**
Как пользователь, я хочу, чтобы сломанный ответ LLM терял максимум одну задачу,
а не завершал приложение.
*Приёмка:* `visitIndex` вне диапазона `0..<count` отбрасывает элемент; остальные
элементы того же ответа сохраняются; процесс жив.
*Провал:* любой индекс приводит к `trimmed[idx]` без проверки нижней границы.

**US-064A-2 — «только эти приложения» значит только их.**
Как пользователь, выбравший режим allowlist, я хочу, чтобы до добавления первого
приложения не снималось ничего.
*Приёмка:* `resolve(mode:"whitelist", appList:"")` даёт активный пустой allowlist;
`isCaptureAllowed` отвечает `false` для любого приложения; в лог уходит одна строка
на приложение с причиной.
*Провал:* пустой allowlist трактуется как «ограничений нет».
*Известная цена:* пользователь, стоявший в режиме allowlist с пустым списком,
раньше снимался целиком, а теперь не снимается вообще. Это исправление приватности,
но функция замолкает молча — видимый статус в Settings нужен в `ITER-072`.

**US-064A-3 — сбой захвата не выключает окно навсегда.**
Как пользователь, я хочу, чтобы неудачная попытка захвата повторилась на следующем
опросе, а не ждала, пока я уйду из окна и вернусь.
*Приёмка:* без принятого кадра `hasChanged` продолжает отвечать `true`; отметка
двигается по тому окну, из которого кадр реально пришёл.
*Провал:* отметка двигается до `await`.

**US-064A-4 — подсказка не стоит в очереди за классификатором задач.**
Как пользователь, я хочу, чтобы решение о подсказке принималось по экрану, на
который я смотрю сейчас, а не через 20 секунд.
*Приёмка:* медленный реактор не задерживает proactive-потребителя; оба получают
один и тот же контекст.
*Провал:* потребители в одной цепочке `await`.

### Corner cases, закрытые тестами

| Случай | Ожидание | Тест |
|---|---|---|
| `visitIndex = -1`, `Int.min` | элемент отброшен, процесс жив | `ScreenExtractorVisitIndexTests` |
| `visitIndex = count`, `Int.max` | элемент отброшен | там же |
| Пустой список визитов, индекс 0 | отброшен | там же |
| allowlist пуст | не снимать ничего | `ScreenContextPolicyTests` |
| Приложение и в blacklist, и в allowlist | исключение побеждает | там же |
| Совпадение по bundle ID или по имени | оба варианта работают | там же |
| Захват упал | окно остаётся кандидатом | `CaptureHighWaterMarkTests` |
| Пользователь переключил окно во время захвата | отметка по фактическому кадру | там же |
| Реактор занят 3 с | proactive стартует сразу | `ScreenContextFanoutTests` |

### Что осталось непроверенным

Живой прогон на подписанной сборке не выполнялся: подтверждено сборкой и
модульными тестами. Реальное поведение захвата с TCC, второй монитор и
поведение allowlist в UI проверяются в `ITER-065` и `ITER-072`.

### Non-goals

- Не вводить `ContextVisitID`, generation, директора, доставку — это `065`+.
- Не трогать промпты, модели, пороги, cooldown.
- Не трогать диктовку, встречи, раскладку и грязный worktree пользователя.
