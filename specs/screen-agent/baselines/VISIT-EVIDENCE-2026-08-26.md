# Доказательства по координатору визитов — 26 авг 2026

**Зачем этот файл.** Ревью Codex по `c8173d3` рекомендовало откатить переход на
координатор: обоснование перехода ссылалось на «четыре часа чистого теневого
прогона, ноль расхождений», а теневой фазы не было — измерение шло через
unified log, который в этой оболочке не читается вообще. Пустой grep был принят
за чистый прогон.

Здесь — то, чем это обоснование должно было быть с самого начала: запросы к
базе, их вывод и дата. База читается, в отличие от лога.

**Источник:** `~/Library/Application Support/MetaWhisp.store`, снято 2026-08-26.

## 1. Вызвал ли переход шторм захвата — нет

```sql
SELECT strftime('%m-%d %H:00', ZTIMESTAMP+978307200,'unixepoch','localtime') h,
       COUNT(*) FROM ZSCREENCONTEXT GROUP BY h ORDER BY h;
```

| час | захватов |
|---|---|
| 08-24 09:00 | 53 |
| 08-24 14:00 | 82 |
| 08-25 10:00 | 30 |
| **08-25 11:00** | **132** |
| 08-25 13:00 | 192 |
| 08-25 16:00 | 186 |
| 08-26 15:00 | 143 |
| 08-26 16:00 | 150 |

Коммит перехода `9dedba8` — **2026-08-25 21:22:11**. Подъём частоты начался в
**11:00 того же дня, за десять часов до коммита**, и после коммита не вырос.
Причина подъёма этим запросом не установлена и остаётся **неизвестной** — это
не «переход ни при чём по другой причине», это «связь не подтверждается по
времени».

Отдельный факт: 143–192 захвата в час выше потолка 30-секундного опроса
(120/час). Значит существует второй путь захвата помимо опроса. Сколько именно
приходится на активацию окна — **не измерено**, счётчика нет.

## 2. Один захват = один визит — и это не поломка идентичности

```sql
-- 26 авг: 1389 захватов, 1357 визитов
SELECT COUNT(*) FROM (
 SELECT ZBUNDLEID b, LAG(ZBUNDLEID) OVER (ORDER BY ZSTARTEDAT) pb,
        ZNORMALIZEDTITLE t, LAG(ZNORMALIZEDTITLE) OVER (ORDER BY ZSTARTEDAT) pt
 FROM ZCONTEXTVISITRECORD
 WHERE date(ZSTARTEDAT+978307200,'unixepoch','localtime')='2026-08-26')
WHERE b=pb AND (t=pt OR (t IS NULL AND pt IS NULL));
```

**Результат: 6.**

Из 1357 визитов только **шесть** случаев, когда одно и то же приложение с одним
и тем же нормализованным заголовком открыло новый визит подряд. Все остальные
визиты чередуются между разными приложениями. Координатор держит один текущий
визит, поэтому уход и возврат — законно новый визит.

То есть 230 визитов Claude за день — это 230 возвратов в Claude, а не 230
ложных срабатываний идентичности. **Основание для отката — шторм идентичности —
данными не подтверждается.**

## 3. Что данные действительно показывают — треть захватов на мельком открытых окнах

Длительности визитов, 26 авг:

|---|---|---|
| 0 с | 196 | 14% |
| 1–4 с | 239 | 18% |
| 5–29 с | 592 | 44% |
| 30–119 с | 276 | 20% |
| 120 с+ | 54 | 4% |

**435 визитов (32%) короче пяти секунд**, и каждый стоил скриншота и OCR
(≈500 мс CPU по замеру 25 авг). Это окна, которые человек пролистнул. Порога
выдержки перед захватом при активации нет.

Это не откат и не баг идентичности — это отдельное решение о поведении, и оно
не принято.
