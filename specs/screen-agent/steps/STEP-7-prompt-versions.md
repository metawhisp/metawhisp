# Шаг 7 — «Стало хуже» можно доказать, а не вспоминать

**Дата:** 2026-08-25
**Статус:** запланирован
**Источник требования:** план §5 «Prompts are versioned code, not anonymous string edits»,
ITER-066 (открытый пункт: prompt V1 descriptor не создан)

---

## 1. Проблема человеческим языком

Сегодня уже был такой случай: я поменял формулировки в промпте, и агент замолчал —
флагманский кейс «оплата Google Ads отклонена» получил оценку 0.00 и «не о чем
говорить». Восстанавливать пришлось по памяти и по логам.

Причина: **промпт — это анонимная строка в коде**. Она меняется, а в журнале
запусков остаётся `promptVersion = ""`. Через неделю на вопрос «после чего агент
стал хуже?» нечего смотреть: строки не подписаны, ран не помнит, какая версия его
породила.

## 2. Решение

Каждый промпт получает **имя и версию**, а журнал запусков — их запись.
Версия считается из самого текста (хеш), поэтому её невозможно забыть обновить:
поменял текст — поменялась подпись.

```
promptVersion = "insight.v3+a41f2c"
                 ^имя  ^семантическая  ^первые 6 символов хеша текста
```

Семантическая часть (`v3`) — то, что ставит человек, когда меняет намерение.
Хеш — то, что не даст соврать: правка «на пару слов» тоже видна.

### Куда пишется

- `ScreenAgentRun.promptVersion` — уже есть колонка, сейчас всегда пустая.
- `ScreenAgentRun.modelRoute` — уже есть, заполняется частично.

После шага любой ран отвечает на вопрос: какой текст промпта и какой маршрут модели
его породили.

### Что это даёт на практике

```sql
-- «после чего упало качество?»
SELECT promptVersion, outcomeReason, COUNT(*)
FROM run GROUP BY 1, 2;
```
Видно: на `insight.v3+a41f2c` — 3 карточки из 40 ранов, на `insight.v3+9be117` —
0 из 60. Ответ найден за минуту, а не за вечер воспоминаний.

## 3. Что подписываем

| Промпт | Где | Имя |
|---|---|---|
| Системный промпт исследователя (решение говорить/молчать) | `InsightPrompts` | `insight` |
| Промпт реактора задач | `RealtimeScreenReactor.systemPrompt` | `task` |
| Промпт часового разбора | `ScreenExtractor.systemPrompt` | `work` |
| Промпт vision (на воркере) | воркер | `vision` — подписываем при следующем деплое воркера |

## 4. User stories

**US-7-1.** Как владелец продукта, я хочу за минуту узнать, после какой правки
промпта агент стал молчать или шуметь.
*Приёмка:* запрос по журналу группирует исходы по версии промпта.

**US-7-2.** Как разработчик, я не хочу иметь возможность поменять промпт и забыть
поднять версию.
*Приёмка:* версия содержит хеш текста; тест падает, если подпись не меняется при
изменении текста.

**US-7-3.** Как пользователь, я не хочу платить за это ни секундой задержки.
*Приёмка:* подпись считается один раз при первом обращении, не на каждый ран.

## 5. Definition of Done

- [ ] `PromptDescriptor` с именем, семантической версией и хешем текста
- [ ] Три клиентских промпта подписаны
- [ ] `beginRun` записывает `promptVersion`, `completeRun` — `modelRoute`
- [ ] Тест: изменение текста промпта меняет подпись
- [ ] Тест: подпись стабильна между запусками процесса (не `hashValue`)
- [ ] Гейт PASS, ревью Codex

## 6. Границы

- Не вводим A/B и не переключаем промпты по версии — только подпись и запись.
- Не переписываем сами промпты в этом шаге (правило: тексты промптов не
  сочиняются без явного разрешения владельца).
