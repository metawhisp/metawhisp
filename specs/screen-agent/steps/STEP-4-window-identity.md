# Шаг 4 — «Два окна одного приложения — это два окна»

**Дата:** 2026-08-25
**Статус:** в работе
**Источник требования:** ITER-065 §3 (фокусное окно как идентичность), ревью Codex по 071.2 (P1 #5)

---

## 1. Проблема человеческим языком

Приложение определяет, «то же самое окно передо мной или другое», **по заголовку окна**.
Заголовок пишет само приложение или веб-страница. Из этого следуют две беды:

**Беда А — два окна слипаются в одно.**
Открыты два окна Safari, оба называются «Inbox». Для MetaWhisp это одно и то же окно.
Текст из одной почты приписывается визиту другой. Дальше по цепочке: факт из одного
письма привязывается к разговору из другого.

**Беда Б — одно окно разваливается на два.**
Ты сидишь в одном окне, страница меняет свой заголовок (счётчик непрочитанных,
название открытой вкладки, таймер). Нормализатор снимает спиннеры и часы, но не всё.
Один заход превращается в цепочку коротких визитов, и время работы дробится.

## 2. Почему так вышло

У системы есть надёжный идентификатор окна — `windowID` из ScreenCaptureKit.
Мы его **уже получаем** (шаг 1 проводки визитов: `ScreenContextSnapshot.windowID`),
записываем в строку визита как справочные данные — но **не используем при сравнении**.

Причина запрета была настоящая: `ContextVisitCoordinator.isSameWindow` сравнивает
`windowID`, только если он есть у ОБЕИХ сторон. Момент решения «захватывать ли»
наступает ДО скриншота, а `windowID` появляется только внутри скриншота. Значит на
входе всегда `nil`, а после захвата — число. Асимметрия `nil` против числа = «другое
окно» = новый визит на каждом тике = шторм захвата. Поэтому действовало правило
**populate-nowhere**: не передавать `windowID` нигде.

## 3. Решение

Взять идентификатор окна **до** скриншота, из Accessibility — там же, где мы уже
берём заголовок и границы окна (`getActiveWindowTitle`, `focusedWindowBounds`).
Тогда обе стороны сравнения получают одно и то же число, асимметрия исчезает.

Если Accessibility идентификатор не отдаёт (частый случай для Electron-приложений) —
поведение прежнее: сравнение по bundleID + нормализованный заголовок. Никакого шторма:
`nil` с обеих сторон — это симметрично.

### Правило сравнения (после шага)

| У визита | У наблюдения | Решение |
|---|---|---|
| есть ID | есть ID | **сравнить ID.** Заголовок не важен |
| нет ID | нет ID | сравнить bundleID + нормализованный заголовок (как сейчас) |
| есть ID | нет ID | считать тем же окном при совпадении bundleID + заголовка (не открывать новый визит из-за пропавшего ID) |
| нет ID | есть ID | то же самое, симметрично |

Третья и четвёртая строки — это и есть починка шторма: пропажа или появление ID
не должна сама по себе означать «другое окно».

## 4. User stories

**US-4-1.** Как пользователь, я хочу, чтобы два окна одного приложения с одинаковым
заголовком считались разными, — чтобы текст из одного не приписывался другому.
*Приёмка:* два окна с равными заголовками и разными системными ID дают два визита.

**US-4-2.** Как пользователь, я хочу, чтобы окно, само сменившее заголовок, оставалось
одним заходом, — чтобы время работы не дробилось на куски.
*Приёмка:* один системный ID + изменившийся заголовок = один визит, поколение +1.

**US-4-3.** Как пользователь, я не хочу, чтобы приложение начало сканировать экран
каждые 30 секунд из-за этой правки.
*Приёмка:* два тика подряд на неизменном окне дают ровно один захват; тест на
пропажу/появление ID.

## 5. Definition of Done

- [ ] Идентификатор окна берётся из Accessibility до захвата и попадает в наблюдение
- [ ] Обе стороны сравнения получают ID симметрично; правило из таблицы §3 реализовано
- [ ] Тесты: два окна/один заголовок; один ID/сменившийся заголовок; ID появился;
      ID пропал; оба без ID (старое поведение)
- [ ] Гейт `scripts/regression.sh` — PASS, число тестов не упало
- [ ] Живая проверка: после установки в базе визитов нет всплеска (сравнение
      количества визитов за час до и после)
- [ ] Ревью Codex

## 6. Риски

| Риск | Что делаю |
|---|---|
| Шторм захвата из-за асимметрии | Правило «пропажа ID ≠ другое окно» + тест на обе стороны |
| AX отдаёт ID не для всех приложений | Фолбэк на заголовок; это ровно текущее поведение |
| ID переиспользуется системой после закрытия окна | Визит и так истекает по 5-минутному разрыву; ID сравнивается только внутри живого визита |
