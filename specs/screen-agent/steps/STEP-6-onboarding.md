# Шаг 6 — «Первое включение объясняет сделку»

**Дата:** 2026-08-25
**Статус:** запланирован
**Источник требования:** ITER-072 (активация, онбординг, раскатка)

---

## 1. Проблема человеческим языком

Экранный агент выключен по умолчанию — это правильно. Но когда пользователь его
включает, он не узнаёт **ни одного** из четырёх фактов, которые определяют, будет
он этой фичей пользоваться или выключит её через день:

1. **Что именно читается.** Только текст активного окна, распознанный на самом Mac.
2. **Что уходит наружу и когда.** Текст — в облако Pro для анализа. Картинка экрана —
   только при отдельном согласии, только один кадр, только когда текста не хватило.
3. **Как часто его будут трогать.** Пауза между карточками, потолок в сутки.
4. **Как это выключить и стереть.** Один тумблер, одна кнопка «удалить историю».

Сейчас всё это либо в настройках мелким текстом, либо нигде. Человек включает фичу
и не знает, во что ввязался, — а через день видит карточку и не понимает, откуда она.

## 2. Что НЕ делаем

- Не делаем многошаговый мастер с картинками. Это выключатель, а не установка ОС.
- Не включаем ничего за пользователя. Онбординг заканчивается его действием, не нашим.
- Не просим разрешения на картинку экрана вместе с основным включением: два разных
  согласия, второе спрашивается позже и отдельно (иначе это тёмный паттерн).
- Не показываем онбординг повторно, если пользователь его закрыл.

## 3. Решение

Одно окно при первом включении Screen Agent. Четыре коротких блока, соответствующих
четырём фактам выше, и одна кнопка. Текст — только правда, проверяемая по коду:

| Блок | Формулировка (черновик, нужен твой ОК) |
|---|---|
| Что читает | «Читает текст активного окна. Распознавание — на этом Mac.» |
| Куда уходит | «Текст уходит в облако MetaWhisp Pro для анализа. Картинка экрана — нет, пока ты отдельно не разрешишь.» |
| Как часто | «Между подсказками — пауза. Не больше N в сутки. Настраивается: Тихо / Обычно / Часто.» |
| Контроль | «Выключается одним тумблером. „Удалить историю экрана“ стирает всё, включая то, что из неё выведено.» |

Значение N подставляется из настоящей настройки (`ScreenAgentPacing.dailyLimit`),
а не пишется в тексте руками — иначе однажды разойдётся с кодом.

**Запрет на выдумки:** каждая фраза должна быть проверяемой по коду. Тест сверяет
числа в тексте с реальными константами.

## 4. User stories

**US-6-1.** Как пользователь, впервые включающий фичу, я хочу за 15 секунд понять,
что читается, что уходит наружу и как это выключить.
*Приёмка:* окно показывается ровно один раз при первом включении; закрывается одной
кнопкой; ничего не включает само.

**US-6-2.** Как пользователь, я не хочу, чтобы согласие на картинку экрана
проскочило вместе с основным включением.
*Приёмка:* в онбординге нет тумблера визуального режима; там сказано, что он
спрашивается отдельно.

**US-6-3.** Как пользователь, я хочу, чтобы обещания в онбординге совпадали с тем,
что приложение делает.
*Приёмка:* числа берутся из констант; тест падает, если текст разойдётся с кодом.

## 5. Definition of Done

- [ ] Окно показывается при первом включении, повторно — нет (флаг в настройках)
- [ ] Четыре блока; числа подставляются из констант, не зашиты в строку
- [ ] Ни одно согласие не выдаётся автоматически
- [ ] Тест «текст не врёт»: дневной потолок в тексте == `ScreenAgentPacing.dailyLimit`
- [ ] Тест «показывается один раз»
- [ ] Гейт PASS, ревью Codex
- [ ] **Твой ОК на формулировки** — это текст, который читает пользователь, я его
      не утверждаю сам

## 6. Открытый вопрос к владельцу

Формулировки в §3 — черновик. Нужен твой ОК или правки: это единственное место
фичи, где текст видит пользователь целиком, а не по кусочку.
